# Quality review · фактический статус

## Проверено автоматически

- XML `pharmacy-order.bpmn` проходит официальный OMG BPMN 2.0 XSD вместе с BPMNDI/DC/DI/Semantic.
- `bpmn-moddle`: 0 предупреждений; ссылки потоков и Call Activity разрешаются; все узлы достижимы от start, у каждого есть путь к end; каждое решение имеет ≥2 именованных условных выхода; каждый узел назначен одной дорожке.
- 6 BPMNDiagram импортированы в bpmn-js без предупреждений и экспортированы в SVG.
- Mermaid parse + render успешно для Task Flow и User Flow; SVG/PNG физически созданы.
- Геометрическая проверка: sequence edges ортогональны и не пересекают внутренность посторонних BPMN-узлов. Проверка не доказывает отсутствие всех пересечений стрелок друг с другом.
- Синтаксис двух Figma async-скриптов проверен локально; это не проверка выполнения Plugin API.
- 33 уникальных ID статичных мобильных макетов; все anchor targets и основные переходы разрешаются.
- PNG signatures/размеры и XML-синтаксис SVG проверены; отчёт — [validation.json](validation.json).

## Визуальный контроль

Просмотрены обзор BPMN, схема оплаты, User Flow и мобильные S08/S11. В ходе контроля исправлены размеры текста/подписей и пересечения sequence flow с блоками. Для чтения широких BPMN использовать SVG с масштабированием и отдельные детализации. Общая User Flow длинная: служит картой всех путей; таблица экранов помогает найти нужный участок.

Индивидуальный визуальный контроль всех макетов, всех state-комбинаций библиотеки и печати не проводился. Структурный проход не выдаётся за полноценное визуальное исследование.

## Согласованность и логика

Task Flow — одна основная покупка; User Flow — пути по интерфейсу; BPMN — процессы и роли. Общая цепочка совпадает. `Payment Unknown` имеет только проверку существующей операции/поддержку; `declined` разрешает новую попытку только после конечного отказа. Оплаченный, но не сохранённый заказ восстанавливается по ID. Refund pending отделён от confirmed.

Выходы вызываемых BPMN-процессов определены в README диаграмм. Концептуальные ветки показывают бизнес-результат, а не автоматически гарантированный ответ внешнего сервиса. Контракты reservations, технических retry, компенсации и human handoff предстоит уточнить при будущей реализации.

## Что не проверено / блокеры

- **Figma Starter MCP limit:** после файла/18 component sets дальнейшая сборка экранов не выполнилась. Figma screenshots, font read-back итоговых экранов, composition QA и проверка prototype links отсутствуют. Текущий нативный файл — исходные компоненты, не законченный экранный прототип. Генератор screens.js сохранён, но его runtime-проверка в Figma не выполнена.
- Локальный HTML/PNG — отдельное статичное представление дизайна, шрифт DejaVu Sans; не экспорт и не pixel parity с Figma Inter.
- Usability-интервью, реальные пользовательские тесты, screen-reader тесты, соответствие WCAG и юридическое соответствие не подтверждались. См. [план](usability-plan.md).
- Реальных API, заказа, оплаты, проверки документа, доставки, отмены, возврата и persistency нет. MVP по запросу отложен.
- Workflow подготовлен; результат GitHub Actions считать неизвестным, пока не получен статус запуска. Локальные проверки выполнены независимо.

## Приёмка по пунктам

1. Task Flow — готов: исходник, цель/актор/условия, SVG/PNG, объяснение и self-review.
2. User Flow — готов: исходник, альтернативы/ошибки/возвраты, SVG/PNG, таблица экранов и матрица исключений.
3. BPMN — готов как концептуальная BPMN 2.0 модель: XML/DI, три типа задач, три дорожки, внешние pools/messages, обзор и детализации, XSD/структурные проверки, SVG/PNG.
4. Figma — **частично, blocked**: файл/компоненты созданы; экранная сборка, доработка controls, нативные интеракции и визуальная приёмка требуют восстановления доступа инструмента. 33 локальных макета доступны для предварительного review.
5. MVP — отложен.
