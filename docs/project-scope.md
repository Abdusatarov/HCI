# Project Scope + Assumptions + Critical User Tasks

## GOAL

Спроектировать интернет-аптеку «Аптека рядом»: уставший или заболевший человек покупает известный ему аптечный товар с доставкой, понимает цену и состояние операции, восстанавливается после ошибок. Текущий этап: проектирование, пункты 1–4; MVP отложен пользователем.

## ASSUMPTIONS

- Адаптивный web, mobile-first: 390 px; контроль reflow при 320 px в будущей реализации. Десктопная композиция: 1440 px.
- Интерфейс на русском; ₸ и адрес — демонстрационные примеры, не юридическое определение рынка. Страну запуска и правила продажи должна подтвердить команда по официальным источникам.
- Основная задача — известный безрецептурный товар. Поиск не диагностирует, не назначает лечение, не подтверждает взаимозаменяемость.
- Наличие, цена, слот и рецепт требуют подтверждения. До оплаты — повторная проверка. Резерв, версия цены и срок слота связаны с попыткой оформления; изменение возвращает пользователя к проверке.
- Один заказ может содержать несколько товаров; главный Task Flow показывает один товар, пограничные случаи описаны в матрице.
- Товары в корзине сохраняются локально без рецептов, данных карты и медицинской истории. Чувствительные документы не должны попадать в небезопасное локальное хранение.
- Реальные исследования, интервью и интеграции не проводились. Персоны — гипотезы. Все статусы в макетах — сценарные.
- Лимит Figma Starter заблокировал создание экранов после создания файла и библиотеки. Поэтому пункт 4 частично готов; локальные PNG не являются экспортом Figma.

## Critical user tasks

1. Найти конкретное название и сверить форму, дозировку, упаковку.
2. Проверить наличие, цену и количество; сформировать корзину.
3. Указать адрес, убедиться в доступности доставки и полной цене.
4. Выбрать оплату, проверить заказ, запустить одну попытку.
5. Отличить подтверждённый успех от ожидания и отказа.
6. Отследить доставку; запросить отмену; отличить запрос возврата от завершённого возврата.
7. Получить помощь или безопасно выйти с сохранённым контекстом.

## Priorities

| Priority | Функции |
|---|---|
| P0 | Поиск, карточка, остаток, корзина, адрес, доставка/ETA, полный итог, проверка сессии, подтверждение, блокировка повторной оплаты, неизвестный статус, рецепт-гейт, восстановление, помощь, доступные ошибки |
| P1 | Отслеживание, задержка, отмена и возврат, категории, частичный остаток, повторное оформление без потери данных |
| P2 | Избранное, аккаунт, история, уведомление о наличии, промокоды — в текущем дизайне не требуются |

## MAIN FLOW

Поиск → карточка → корзина → адрес → доставка → оплата → проверка → обработка → подтверждённый заказ → отслеживание.

## ALTERNATIVE FLOWS / ERROR / RECOVERY CASES

См. [матрицу исключений](edge-cases.md), [переходы экранов](screen-map.md), [BPMN](../diagrams/README.md). Для каждого recoverable failure есть понятное действие; ожидание с ID операции — самостоятельный честный результат, не success.

## ACCESSIBILITY CONSIDERATIONS

Designed toward WCAG 2.2 AA: labels, текстовые ошибки, независимость от цвета, целевые CTA от 48 px, видимый focus, логичный Tab. Статические макеты не доказывают доступность будущей реализации. Ручные проверки клавиатуры, screen reader, zoom и reflow ещё предстоят.

## OPEN RISKS

Юрисдикция, лицензирование, разрешённые категории доставки, порядок проверки рецепта, реальные SLA API, резерв товара до оплаты, политика отмены, срок возврата, проверка противоречащих ответов провайдера, privacy/security требуют решений до запуска. Никаких обещаний «соответствует закону» или «подходит пользователю».
