| E25 P1 | Пользователь отменяет | Сначала проверим возможность отмены | До оплаты — выйти; после — остановить исполнение подтверждённо | S15 / Fulfilment |
| E26 P1 | Refund initiated / pending / unknown | Возврат запрошен; ожидаем подтверждения | Один запрос; опрос статуса, помощь по ID | S27, S28 / Fulfilment |
| E27 P1 | Refund completed | Возврат подтверждён | Терминальное состояние только по ответу провайдера | S33 / Fulfilment |

Один пользовательский жест запускает одну payment operation. Повтор HTTP-запроса использует прежний ключ; новая бизнес-попытка разрешена только после подтверждённого конечного отказа/отмены. Unknown не превращается в declined по таймеру. Оплаченный, но не записанный заказ требует reconciliation; в этой учебной модели дальнейшее ручное разрешение отражено как отложенная проверка с ID.

Ссылки на состояния обозначают дизайн и процесс, а не реализованные интеграции. Подробные состояния компонентов представлены в Figma; законченные нативные экранные композиции пока заблокированы тарифным лимитом.
