# Screen / Trigger / State / User Action / Next State

Информационная архитектура: Home → Search/Category → Product Detail → Cart → Checkout (Address, Delivery, Payment, Review) → Processing → Order Success → Tracking; Help доступна с каждого этапа. Account опционален и исключён из текущего scope.

ID совпадают с User Flow и локальными макетами. Нативная сборка экранов Figma заблокирована тарифным лимитом; эта таблица — спецификация. Переходы локального HTML демонстрируют заранее подготовленные состояния, а не запросы к API. Возврат из помощи к исходному контексту — через Back браузера; для Figma нужен Back action.

## Accessibility notes

Каждый экран имеет заголовок и одну основную цель; CTA ≥48 px; ошибки выражены текстом; в будущей реализации нужны связанные labels, aria-describedby, объявления статуса и управление focus. Не считать статическое представление полей рабочими доступными формами. Состояния Loading/Disabled не полагаются исключительно на spinner или цвет.

## Exception paths / self-review

S16/S17 → поиск; S18 → каталог; S19/S20/S21 → проверка/помощь/удаление; S22 → корзина; S23/S24 → адрес; S25 → восстановление; S12 → другой способ; S11/S26 → существующая операция; S14 → tracking; S15 → запрос отмены; S27/S28 → проверка возврата; S33 → завершение. Последнее подтверждение каждого этапа показано отдельно от ожидания. Все эти состояния специфицированы; отсутствие полного нативного Figma-прототипа отражено в статусе пункта 4.
